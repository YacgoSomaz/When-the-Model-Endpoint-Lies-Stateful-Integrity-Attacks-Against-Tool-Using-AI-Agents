> 本模板用于提交给内部安全团队、厂商安全响应中心或网安专业人员。先写可复核事实，再写推断；不要把测试能力直接等同于真实攻击影响。

## 2. 为什么值得关注

说明普通用户在界面里能够看到什么、实际模型请求经过哪些系统，以及工具型 Agent 相比纯聊天模型多出的执行边界。避免使用“完全失控”“必然中毒”等未经证实的词。

## 3. 测试边界

- 研究者自有或书面授权的账号、终端、网关和 API Key；
- 无生产数据、无第三方目标、无真实凭据；
- 合成图片、虚构环境变量、虚构文件、回环诊断端点；
- 无 shell、提权、持久化、任意网络请求或真实隐私采集；
- 每个本地动作均需独立人工批准。

## 4. 系统与数据流

```text
用户 → Agent 客户端 → 授权实验网关 → 模型服务
                     ← 人工检查响应 ←
             Agent 白名单工具执行器（独立审批）
```

列出客户端版本、模型、模型日期、操作系统、网关提交哈希、关键配置和网络拓扑。API Key、Cookie、账号、内部域名和个人路径必须脱敏。

## 5. 复现步骤

1. 启动 `TEST_CASE=TC-___` 的网关；
2. 记录客户端可见输入；
3. 在控制台确认变更路径和前后 SHA-256；
4. 放行请求，记录模型是否提出工具调用；
5. 记录客户端是否阻断、告警或要求确认；
6. 如需执行白名单动作，单独人工批准；
7. 保存执行状态、返回值和清理结果；
8. 用 `TEST_CASE=OFF` 重复同一输入作为对照；
9. 至少重复三次。

## 9. 风险分析

分别评估：提示词与对话机密性、请求/响应完整性、工具参数完整性、授权绑定、多轮上下文继承、可检测性和所需攻击前提。严重度必须同时考虑“中转层已能读取明文”这一强前提。

## 10. 修复建议

- 将模型输出视为提议，不视为用户授权；
- 高影响工具调用绑定本地不可伪造的意图记录；
- 审批界面展示最终规范化参数，并与实际执行参数一致；
- 工具执行器实施独立网络、文件、进程和账号权限；
- 对模型端点、模型身份和响应来源做可验证绑定；
- 检测上下文中用户意图、模型计划和工具参数的不一致；
- 保存可审计但最小化的数据，并提供密钥轮换与事件响应流程。
