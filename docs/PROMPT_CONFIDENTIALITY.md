# 中转站为什么能看到提示词和对话

## 关键事实

OpenAI 兼容请求通常不只包含用户当前输入，还可能包含 `messages`、`tools`、模型参数和历史工具结果。客户端或 SaaS 后端把这些 JSON 发给哪个服务，哪个服务就能在自己的 TLS 终止点读取它们。

因此，把模型 URL 换成第三方兼容地址可能同时暴露：

- 系统提示词与开发者指令；
- 用户当前消息和历史对话；
- 工具 schema、工具选择规则与权限线索；
- 工具调用参数和工具执行结果；
- 模型、采样、上下文和客户端环境元数据；
- 用于上游转发的 API Key（若客户端直接把真实 Key 交给中转方）。

## TLS 没有失效

这不是“破解 HTTPS”。连接到中转站时，中转站就是 TLS 的合法对端；连接到模型时，它又建立另一条 TLS 连接。加密能防止链路外的旁观者，但不能阻止合法接收者读取收到的数据。

## 完整提示词样本的意义

仓库中的完整脱敏样本用于证明三件事：

1. 实际请求远大于用户界面里看到的一句话；
2. 系统提示和工具定义可能具有商业与安全价值；
3. 中转层既是完整性风险，也是机密性和隐私风险。

样本保留原有 JSON 结构、消息顺序、系统提示语义和工具 schema，但删除身份信息和凭据。它是披露前的私有证据，不代表已经获得公开第三方提示词的许可。

## 防御建议

- 只向可信服务发送系统提示和用户数据；
- 使用短期、限额、专用 Key，不与其他业务共用；
- 对企业网关建立合同、访问控制、审计和最小数据保留；
- 尽量减少发送到模型的历史、路径、环境和用户数据；
- 对敏感信息先在客户端脱敏；
- 把高度机密的提示和数据放在本地策略层，而不是每轮完整发送；
- 对请求/响应建立可验证摘要或签名，并明确真实网络路径。
