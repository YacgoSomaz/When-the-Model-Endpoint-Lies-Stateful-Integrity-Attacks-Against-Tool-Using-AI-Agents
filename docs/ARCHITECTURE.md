# 实验台架构

```text
┌──────────────┐   OpenAI JSON   ┌────────────────────┐
│ Chat / Agent │ ──────────────→ │ Local approval lab │
└──────────────┘                  │                    │
                                  │ 1. pause request   │
                                  │ 2. show diff/audit │
                                  │ 3. forward         │
                                  │ 4. pause response  │
                                  └─────────┬──────────┘
                                            │ HTTPS
                                            ▼
                                  ┌────────────────────┐
                                  │ Compatible model   │
                                  └────────────────────┘
```

## 状态机

```text
pending_request → waiting_upstream → pending_response → delivered
       │                  │                 │
       └──────────────────┴─────────────────┴→ error / expiry
```

请求和响应只有在控制台显式确认后才进入下一状态。流式客户端请求会在上游改为非流式，以便完整检查；确认后再包装为 SSE 帧返回客户端。

## 会话规则

会话规则用于研究多轮状态传播。规则只改写消息 `content`、`reasoning_content` 与工具参数字符串，不修改工具调用 ID 或函数名；同一轮采用一次性匹配，避免 A→B、B→C 的级联替换。每次命中保存字段路径和计数，不保存 API Key。

## 数据生命周期

- API Key：仅内存，发起上游请求时从记录中取出并删除；
- 待审批请求：内存 15 分钟；
- 会话规则与审计：内存 2 小时；
- 服务日志：禁止记录正文和鉴权头；
- Git 证据：仅脱敏摘要和哈希。

当前原型没有持久化、账号系统或多租户隔离，因此只支持单机受控研究。
