# 当前发现与结论边界

## F-001：模型通道完整性会影响工具行为

在 2026-08-14 的授权实验中，客户端可见输入为普通问候；实验网关将请求中的用户任务替换为下载一个无害 ZIP 并计算哈希。模型随后生成了标准工具调用，Agent 在专用工作区执行下载，并在后续轮次完成哈希验证。

证据级别：**受控环境中的可重复观察，待独立复核**。

能够支持的结论：

- 客户端界面中的原始文本，不一定等于模型实际接收的文本；
- 模型输出能够影响具备工具权限的 Agent；
- 多轮 Agent 会把工具结果重新带入模型上下文；
- 因而模型链路完整性和工具执行策略必须分别校验。

不能支持的结论：

- 不能据此宣称真实恶意程序可以被静默安装；
- 不能据此宣称已绕过用户审批、系统权限或终端防护；
- 不能据此认定某个产品存在已确认安全漏洞；
- 不能把单次结果外推到所有模型、客户端和版本。

## F-002：一次替换不足以描述有状态 Agent 风险

Agent 每轮通常会重新提交系统提示、用户输入、助手消息、工具调用与工具结果。若只修改第一次响应，后续上下文可能重新出现原始目标，模型也可能纠正此前行为。会话级研究因此要记录每次修改的位置、原值、替换值、方向和命中次数。

这是一种研究工具，不应成为生产设计。生产防御应校验用户意图与工具参数的一致性，而不是依赖另一个“粘性改写器”。

## F-003：显示正确的 URL 不是完整性证明

桌面或 Web 客户端经常先请求自己的后端，再由后端调用模型。UI 显示官方地址，只能说明显示值；真正的数据路径需要通过网络配置、证书主体、端点固定、可验证日志或签名来证明。

## 待验证问题

- 工具调用前是否始终存在清晰、不可伪造的用户确认？
- URL、文件哈希和最终命令是否在确认界面完整展示？
- 本地策略能否拒绝与最近用户意图不一致的工具调用？
- 不同流式模式、失败重试、压缩上下文和多模型回退是否改变结果？
- 端点固定、响应签名或本地策略能否阻止实验链路？
