# 缓解方案

## Agent 客户端

1. **端点真实性**：把实际连接端点、证书主体和是否经过企业代理作为可核验状态，而非普通文本配置。
2. **用户意图绑定**：为高影响操作生成不可变的本地意图记录；工具调用必须引用该记录，并由本地策略比对目标、域名、路径和动作。
3. **工具最小权限**：默认只读；文件写入限定工作区；网络访问、执行、安装和提权分别授权。
4. **结构化审批**：审批界面显示规范化后的真实参数，而不是模型摘要。长参数不能折叠掉关键 URL、文件名或命令。
5. **响应不可信**：模型返回的 Markdown/HTML/JSON 只作为数据解析；禁止隐式脚本执行、模板求值和命令拼接。
6. **跨轮重新授权**：历史上下文不能自动延续敏感许可；重试、回退和新工具调用都要重新通过策略。

## 模型网关与 SaaS 后端

- 将请求/响应变更记入不可抵赖审计，记录哈希而非秘密值；
- 明确区分透明转发、策略变换和内容改写；
- 控制台必须强鉴权、TLS、最小权限、短会话和访问告警；
- API Key 使用专用短期凭据，限制模型、额度、来源和有效期；
- 为规范化请求和响应提供签名或可验证摘要；
- 禁止静默将用户配置的官方端点替换为其他端点。

## 工具执行器

- 使用命令/参数 AST 或固定 API，不把模型文本直接交给 shell；
- 对网络目标使用域名允许列表、DNS 重新绑定防护和重定向限制；
- 下载前限制协议、大小、MIME、扩展名，下载后校验发布者与哈希；
- 把“下载”和“执行/安装”拆成独立权限；
- 对工作区外路径、持久化位置和系统目录默认拒绝；
- 记录规范化后的最终执行值，并向用户展示同一个值。

## 可能的研究原型

```text
UserIntent = Sign_local(canonical(action, target, constraints, expiry))
ToolCall   = { action, target, constraints, intent_id }

allow iff:
  verify(UserIntent)
  AND fields(ToolCall) subset-of fields(UserIntent)
  AND local_policy(ToolCall)
  AND user_confirmation_matches(ToolCall)
```

签名不是万能方案：如果客户端本身被攻破，签名也会失去意义。它的价值是把模型和中转层从“授权来源”降级为“候选计划生成器”。
