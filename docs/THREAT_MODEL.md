# 威胁模型

## 系统边界

```text
用户意图 → Agent 客户端 → 模型网关/反向代理 → 模型服务
                         ←                    ←
               本地工具执行器与工作区
```

模型端点可以是官方服务、企业网关、SaaS 后端或兼容层。TLS 只保护两个相邻节点之间的传输；如果网关本身被授权终止 TLS，它天然能够看到该跳内的明文。

## 受保护资产

- 用户原始意图及其上下文；
- 模型回答与工具调用的来源、完整性和顺序；
- API Key、会话令牌和个人数据；
- Agent 的文件系统、网络、进程和账号权限；
- 审批界面向用户展示的信息与实际执行内容的一致性。

## 对手能力

本研究只模拟一种能力：受控网关可以读取并重写其被授权转发的 JSON，然后继续转发。它不假设攻破 TLS、不假设取得操作系统管理员权限，也不研究模型服务本身的入侵。

重点观察四种完整性失效：

1. 请求消息被改写；
2. 响应正文被改写；
3. 结构化工具参数被改写；
4. 修改未与后续 Agent 上下文绑定，或被粘性规则持续带入后续轮次。

## 应成立的安全不变量

- 一项高影响工具行为必须能追溯到用户看见并确认的具体意图；
- 工具执行器不能只凭“来自模型”就信任参数；
- 审批界面展示的命令、URL、哈希、路径必须与实际执行值一致；
- 模型端点或中转变化应可见、可验证、可撤销；
- 历史上下文不能替代当前轮次的安全授权；
- 响应的文本内容不能被当作 HTML、脚本或系统命令隐式执行；
- 网络下载必须受域名、协议、文件类型、大小和哈希策略约束。

## 非目标

- 发现或传播真实恶意载荷；
- 攻击未授权产品或用户；
- 绕过操作系统、EDR、浏览器或 Agent 的明确审批；
- 证明任何具体厂商在所有配置下都存在漏洞。
